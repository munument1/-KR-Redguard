# UTF-8 엔진 패치와 배포 패처 개발

**후속 갱신 (2026-10-13):** Software UTF-8 그리기·너비 계산 후크를 연결한 시험 EXE를 생성했다. 자동 테스트 49개와 실제 생성 EXE의 격리 출력 검사를 통과했다. 설치 가능한 완성 패치는 아니며 실제 DOS/게임 실행 및 자막 분할 연결은 남았다. [실행 안내 및 최신 범위](TEST_EXE.md).

사용자가 UTF-8 지원을 우선하고 최종 배포물은 사용자 설치본에 적용하는 패처로 제공하기로 했다. 게임 실행 파일 자체는 배포하지 않는다. 현재는 개발 중이며 설치 가능한 한국어 패치가 아니다.

## 구현한 부분

- `tools/encoding/utf8_x86.py`: 버퍼 길이를 받는 32비트 x86 UTF-8 디코더. 결과는 코드포인트와 소비한 바이트 수다. ASCII, 2~4바이트 Unicode, 잘못된 시퀀스, 과잉 인코딩, surrogate, 범위 초과, 잘린 입력을 처리한다.
- 출력 바이너리는 214바이트이고 외부 함수 호출과 절대 주소 참조가 없다. 다만 원본 게임 함수의 호출 규약과 다르므로 현재 바이너리를 그대로 덮어쓰면 안 된다. 게임 함수는 EDX 보존을 포함하는 기존 계약을 사용하며, 새 디코더의 EDX는 소비 바이트 수다. 어댑터와 루프 수정이 함께 필요하다.
- `tests/test_utf8_x86.py`: Unicorn으로 실제 기계어를 실행한다. 한글 완성형 11,172종, 현재 번역의 전체 고유 문자 1,059종, 유니코드 경계 및 잘못된 UTF-8을 검사했다. 입력을 매핑된 페이지 끝에 배치해 잘린 입력의 범위 밖 읽기를 검사한다. 보존 대상 레지스터와 스택 복원도 검사한다.
- `tools/patch/binary_patcher.py`: 단일 파일용 SHA-256 기반 패처. 원본 크기·해시 및 변경 전 명령 바이트 검증, 변경 후 전체 해시 검증, 백업, 임시 파일을 이용한 교체, 원본 복원을 구현했다. 변경된 다른 모드 파일 및 손상된 백업은 거부한다.
- 패처 테스트는 합성 파일에서 수행했다. 원본 게임에는 적용하지 않았다.

이번 작업 종료 시 자동 테스트 **30개 통과**. 디코더 검사는 5개 테스트 메서드 안에서 다수 문자와 잘못된 입력을 반복 실행한다. 이 결과는 게임 내 표시 성공을 의미하지 않는다.

## 로컬 빌드 및 검사

현재 개발용 종속성은 Git 제외 경로 `output/engine_utf8/deps/`에 있다. 다른 환경에서는 다음 명령으로 준비한다.

```powershell
python -m pip install --target output/engine_utf8/deps keystone-engine unicorn
python tools/encoding/utf8_x86.py
python -m unittest discover -s tests -v
```

분석 도구는 별도로 `capstone`을 사용한다. 런타임 생성물은 `output/engine_utf8/runtime/`에 저장한다. 외부 패키지 DLL과 개발 환경은 최종 게임 배포물에 그대로 포함하지 않는다.

## 패처 명세

패치 매니페스트는 `redguard-binary-patch-v1` 형식으로 원본·출력의 SHA-256과 크기, `edits` 배열을 가진다. 각 변경은 파일 `offset`, 16진수 `before`, `after`다. 같은 길이의 덮어쓰기 또는 EOF 추가만 허용하고 겹치는 변경은 거부한다. 임의 명령이나 코드를 실행하는 필드는 없다.

`check`는 입력과 변경 결과를 메모리에서 검증하고 파일을 쓰지 않는다. `apply`는 백업 후 교체하며 `restore`는 해시가 일치하는 백업으로 복원한다. 백업은 대상 파일명 뒤 `.redguard-ko.bak`를 붙여 보관하고 복원 이후에도 유지한다. 자동 복원 및 게임 실행은 수행하지 않는다.

```powershell
# 아래는 검증된 게임용 매니페스트가 만들어진 후 사용할 인터페이스다.
python tools/patch/binary_patcher.py check '<설치 폴더>/RG.EXE' '<배포 매니페스트>.json'
python tools/patch/binary_patcher.py apply '<설치 폴더>/RG.EXE' '<배포 매니페스트>.json'
python tools/patch/binary_patcher.py restore '<설치 폴더>/RG.EXE' '<배포 매니페스트>.json'
```

실제 게임용 매니페스트는 아직 없다. `game_verified`가 참이 아닌 개발 매니페스트는 적용을 거부한다. 이 플래그는 빌드 담당자의 검증 기록 표시이며 암호학적 서명이나 제3자 검증을 대신하지 않는다. 최종 배포 시 매니페스트도 패처와 함께 신뢰할 수 있는 릴리스에서 제공해야 한다.

## 글리프·줄바꿈 후속 구현

별도 유니코드 폰트 포맷과 x86 글리프 조회·줄바꿈 코어를 추가 구현했다. 1,206글리프 개발 팩으로 번역 4,866건의 x86 레이아웃 검사를 통과했고 전체 테스트는 40개다. 게임 함수에 연결되지는 않았다. [상세 기록](UNICODE_GLYPHS_AND_WRAPPING.md)을 참고한다.

## 완료하지 않은 핵심 작업

1. 원본 문자 함수의 직접 호출 후보를 추적하고 모든 문자열 처리 루프를 검증한다. 후보는 `output/engine_utf8/engine_utf8_report.json`의 `direct_call_candidates`에 저장했다. 바이트 검색 후보이므로 코드 경계 확인이 필요하다.
2. 고정 256글리프 테이블을 대체할 저장 구조를 구현하고 폰트 적재·그리기·해제 경로에 연결한다.
3. 새 UTF-8 디코더를 호출하는 어댑터와 문자별 이동·너비·줄바꿈 처리를 구현한다.
4. DOS 세그먼트 및 LE fixup에 맞게 코드를 배치하고 테스트 복제본을 만든다.
5. 실제 게임에서 자막·HUD·메뉴를 확인하고 그 결과에 맞춰 배포용 차분 매니페스트를 생성한다.
6. 패처를 사용자가 Python을 설치하지 않아도 실행할 수 있는 Windows 실행 파일로 묶고 실제 설치·복원을 검증한다.

**개발 중인 디코더와 패처 기반만 완성됐다. UTF-8 게임 지원, 한글 글리프 출력, 설치 패키지 완성은 아직 주장하지 않는다.** 번역 검수 진행 기록은 이 작업에서 변경하지 않았다.
